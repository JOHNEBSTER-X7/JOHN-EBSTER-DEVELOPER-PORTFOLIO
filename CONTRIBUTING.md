# Contributing and project standards

This repository is a personal engineering portfolio. Contributions, review suggestions and issue reports are welcome.

## Before submitting changes

- Explain the problem and intended behaviour.
- Keep changes focused and document relevant trade-offs.
- Add or update automated tests where practical.
- Run the documented checks and report the result accurately.
- Never commit API keys, credentials, private keys, seed phrases or personal data.

## Documentation checklist

Each project should provide:

- Purpose, scope and current status
- Technology stack and prerequisites
- Installation and configuration instructions
- Run and test commands
- Architecture overview and important design decisions
- Known limitations and security considerations
- Example requests or screenshots where useful

## Commit messages

Use clear, descriptive messages such as:

- `feat: add signal filtering endpoint`
- `test: cover multisig confirmation threshold`
- `docs: explain local development setup`
- `fix: validate malformed request input`
